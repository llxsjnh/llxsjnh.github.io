初识Hexo，却在Github Pages上栽跟头

发表于2026-01-17|更新于2026-01-17|Hexo
|浏览量:

hexo deploy命令用来部署网站。执行该命令会在部署前自动生成静态文件，且如果设置了有效部署器，会生成.deploy_git文件夹。在配置文件中，有效的部署配置必须包含 type字段，并指定部署的 repo和 branch。

本人使用了github进行网站托管，参考了以下文章：

  • GitHub Pages介绍(GitHub提供的免费静态网站托管服务，允许用户通过GitHub仓库直接创建和发布网页)-CSDN博客
  • 超详细Hexo+Github Pages搭建个人博客教程 - 俗愿· - 博客园
  • 使用Hexo搭建可自动同步的个人博客 - MaphicalYng

根据上述文章建立好github仓库后，进行部署，出现以下问题：

fatal: unable to access “配置文件repository的值”: Failed to connect to github.com port 443 after 21082 ms: Could not connect to server.

在查阅资料后，猜测可能的原因是：仓库没有可用的SSH。也确实如此。因此，在本机生成了SSH Key后将公钥添加到Github，部署成功。同时，在仓库源码页面看到了提交上去的内容。提交的内容实际上是执行 hexo generate生成的诸多静态文件（在public文件夹中）。但是，访问网站时出现了新的问题：404错误。

再次查阅资料，我觉得【终于解决了hexo发布到GitHub出现404的问题了】_hexo 上传成功,github无法访问-CSDN博客这篇文章说的有点道理。我一开始也以为是其中提到的分支问题，因此全改用master。后来发现不是，我其实已经部署成功了。只不过在建立仓库是使用了项目站点而非用户站点，访问路径不正确导致的。建立用户站点仓库的名词格式必须是“github用户名.github.io”，这样才可以通过 https://github用户名.github.io进行访问。

然而，我在重新建立了用户站点后，仍然无法正常访问。我想起之前某些文章中提到的需要README文件。果然，添加了README文件后，网站可以正常访问了。实际上，在建立仓库时有初始化README，但似乎被初次部署给冲掉了。

总结一下，使用Github Pages发布Hexo个人网站时需要注意的地方有：

  1. github仓库名词必须按照“github用户名.github.io”格式填写
  2. hexo配置文件中，url字段必须是 https://github用户名.github.io；在部署部分，repo字段（仓库ssh地址）和 branch字段（分支名称）需要填写正确
  3. 仓库没有ssh地址时，必须为本机生成SSH Key，并将公钥配置给Github
  4. 初次部署后，必须添加README文件。
